This permissions model takes effect on **October 18, 2026**. Before then, Kroo has only two user types: **Admins** and **Non-Admins**.
</Info>

Roles are the primary way to manage permissions in Kroo. Each role grants access to Kroo **Features** and to individual **Connections**, and is then assigned to users. A user can have multiple roles.

## Features

    | **Membership** | Add or remove users from Kroo. |

  </Tab>
  <Tab title="AI Tools">
    | Feature | What it grants |
    |---------|----------------|

    | **Kris › Administration** | View Kris usage. |
    | **Kris › Context** | Manage company-wide context fed to Kris. |
    | **Kris › Document** | Connect external [document sources](/document-sources), such as SharePoint. |
    | **Kris › Prompts** | Manage company-wide sample prompts. |
    | **Kris › Tables** | Toggle **Include in AI Enterprise Search** per table in the Data Dictionary. Tables are included by default; excluded tables are still available to Kris and MCPs, but deprioritized. |
    | **MCP** | Configure [Kroo MCPs](/kroo-mcp-setup) and connect external AI tools such as Claude or Microsoft Copilot. |
  </Tab>

## Connections

Connections are your company's data connectors. For each connection, a role can be granted one of three levels:

| Level | What it grants |
|-------|----------------|
| **Read** | View pipeline analytics and configuration |
| **Configure** | Read, plus configure modules inside the connector |
| **Manage** | Configure, plus manage connector details |

<Warning>
Connection access lets users configure a pipeline, but does not let them see its data. Data access is managed through [Database Access and Row-Level Permissions](/permissions/row-level-permissions).
</Warning>

## Structuring roles

Roles form a hierarchy:

- The **Owner** sits at the top and has access to everything. Owners can only be designated by the Kroo team at your company's direction.
- Owners create higher-level roles first, then child roles beneath them.
- A child role's permissions are chosen from its parent's — a child can never have more access than its parent.

When a user has multiple roles that grant different levels of access to the same feature or connection, the **highest level wins**. All of a user's roles combine into a single set of permissions.

</Info>

Row-Level Permissions (RLP) control which tables, and which rows within those tables, each user can see in a database. RLP applies everywhere Kroo data is shown — the Data Viewer, Studio dashboards, Kris, and MCPs.

## Prerequisites

- **Database Access** to the database at the [resource level](/permissions/resources), for users who need to see its data
- **Data Warehouses** and **Row Level Permissions** [role features](/permissions/roles), for admins who configure RLP
- A **Microsoft SQL** or **Microsoft Fabric** data destination

<Warning>
Database Access alone does not show any data. Users must also belong to at least one RLP group that grants access to a table.
</Warning>

## Groups

RLP is organized around **groups**. Each group defines which tables its members can see and which rows within each table. Roles and users are then assigned to the group.

A user can belong to multiple groups — their effective access is the **union** of all their groups.

<Frame>

Groups have one of two origins:

- **Custom** — groups you create and edit
- **Kroo Synced** — groups managed by Kroo. **Admins (Kroo Managed)** is created automatically, contains all RLP admins, and grants access to every table. It can be viewed and duplicated but not edited.

## Table access

For each table in a group, choose a filter type:

<Tabs>
  <Tab title="No Filter (Full Access)">
    Members see **all rows** in this table. Use this when the table doesn't contain sensitive data or when members should have unrestricted access to it.
  </Tab>
  <Tab title="Conditions">
    Build a row filter with the point-and-click condition builder.

    | Field | Description |
    |-------|-------------|
    | **Column** | The column to filter on (e.g., `project_id`, `company`, `region`) |
    | **Operator** | The comparison: `equals`, `not equals`, `contains`, `greater than`, `less than`, etc. |
    | **Value** | The value to match (e.g., `123`, `West`, `Active`) |

    When multiple conditions are added, choose a logic mode:

    - **ALL conditions must match (AND)** — every condition must be true for a row to be visible
    - **ANY condition must match (OR)** — at least one condition must be true

    **Example:** to restrict members to Project ID 123 in the `kroo_procore.projects` table, set Column = `project_id`, Operator = `equals`, Value = `123`.
  </Tab>
  <Tab title="Raw SQL">
    Write a custom SQL `WHERE` clause for advanced filtering — useful when conditions are complex or need to reference other columns dynamically.

    ```sql
    region = 'West' AND status != 'Closed'
    ```
  </Tab>
</Tabs>

<Info>
Use **Preview Table Data** to see the table's columns and sample rows before building your filter.
</Info>

## Creating a group

<Steps>
<Step title="Open Row-Level Permissions">
  In **Database Access**, select **Row-level permissions** on the database you want to configure, then click **Create group**.
</Step>

<Step title="Name and describe the group">
  Enter a **Group name** (e.g., "West Region PMs" or "Subcontractor – Acme") and an optional **Description**, then click **Continue to logic**.

  <Frame>
    <img
      src="/images/permissions/rlp-new-group.png"
      alt="New group wizard on the Table and Row Logic step with no tables added"
    />
  </Frame>
</Step>

<Step title="Add tables">
  Click **Add Table**, select the tables to grant access to, and click **Add**. You can add up to 100 tables at a time.

  <Frame>
    <img
      src="/images/permissions/rlp-add-tables.png"
      alt="Table Access picker with schema filters and one table selected"
    />
  </Frame>

  <Warning>
  Newly added tables grant **full access** until you configure a row filter.
  </Warning>
</Step>

<Step title="Set row filters">
  Expand each table with the chevron next to its name, choose a [filter type](#table-access), and click **Save Filter**. Save each filter before continuing, then click **Continue to role access**.

  <Frame>
    <img
      src="/images/permissions/rlp-filter.png"
      alt="Conditions filter on a table where user_type equals 3"
    />
  </Frame>
</Step>

<Step title="Assign roles and users">
  In the access pane, choose which roles and users belong to the group. See [Granting access](/permissions/resources#granting-access) for how role assignments work.
</Step>
</Steps>

Groups can be edited later from the Row-Level Permissions page. To check a group's filters from a member's point of view, use **Test as User** in Kris AI Context Settings.

<Info>
This permissions model takes effect on **October 18, 2026**. Before then, Kroo has only two user types: **Admins** and **Non-Admins**.
</Info>

Both **Database Access** and **Row Level Permissions** are managed using the [Resource Access Pane](/permissions/resources). Databases are where your connection data lives once it is brought into Kroo. Databases can be managed in one of 3 configurations:

1. Kroo hosted Data Warehouse
2. Client hosted Data Warehouse
3. Multiple client hosted Data Warehouses

<Info>
Kroo supports connection to a wide variety of Data Destination Platforms. Currently, only Microsoft SQL and Microsoft Fabric data destinations are compatible with Kroo's Row Level Permissions capabilities.
</Info>

Data brought into the Kroo platform may be sensitive in nature such as financial or performance management data. Managing the Database Access at the resource level will control that database's user/group specific visibility within the Kroo app. Row Level Permissions are then used to control which database tables and rows a user sees within the database itself. RLP is needed for users to view data even if Data Warehouse access is granted at the resource level. To configure RLP (row level permissions), select `Row-level permissions` in the desired database. This will open the Row Level Permissions window:

<Frame>
  <img
    src="/images/permissions/rlp-groups.png"
    alt="Row-Level Permissions window listing groups"
  />
</Frame>

Row Level Permissions are managed in groups. To create a new group, simply select **+ Create Group**. In the New Group window, enter a `Group name`, a `Description (optional)` and select **Continue to logic**.

In the following window, you can select which tables to include in the group and rules that govern their visibility. To do so select `+ Add Table`.

<Frame>
  <img
    src="/images/permissions/rlp-new-group.png"
    alt="New group window on the Table and Row Logic step"
  />
</Frame>

Then select the Table(s) you would like to grant access to and select `Add table(s)`:

<Frame>
  <img
    src="/images/permissions/rlp-add-tables.png"
    alt="Table Access picker with one table selected"
  />
</Frame>

Then expand your selected table(s) out by clicking the chevron next to the table name and select your desired filter type. Options are:

- No filter (full access)
- Conditions
- Raw SQL

Define your preferred Filter(s) if applicable, select `Save Filter` and then `Continue to role access`.

<Frame>
  <img
    src="/images/permissions/rlp-filter.png"
    alt="Conditions filter on a table"
  />
</Frame>

At this point you will be brought to the Resource Access Pane where you can set which specific roles and/or which specific users should be included in this group of Row Level Permissions. Row Level Permissions can be revised and edited in the future from the Row Level Permissions window.

## Filter types

<Tabs>
  <Tab title="No Filter (Full Access)">
    Members see **all rows** in this table. Use this when the table doesn't contain sensitive data or when members should have unrestricted access to it.
  </Tab>
  <Tab title="Conditions">
    Build a row filter with the point-and-click condition builder.

    | Field | Description |
    |-------|-------------|
    | **Column** | The column to filter on (e.g., `project_id`, `company`, `region`) |
    | **Operator** | The comparison: `equals`, `not equals`, `contains`, `greater than`, `less than`, etc. |
    | **Value** | The value to match (e.g., `123`, `West`, `Active`) |

    When multiple conditions are added, choose a logic mode:

    - **ALL conditions must match (AND)** — every condition must be true for a row to be visible
    - **ANY condition must match (OR)** — at least one condition must be true

    **Example:** to restrict members to Project ID 123 in the `kroo_procore.projects` table, set Column = `project_id`, Operator = `equals`, Value = `123`.
  </Tab>
  <Tab title="Raw SQL">
    Write a custom SQL `WHERE` clause for advanced filtering — useful when conditions are complex or need to reference other columns dynamically.

    ```sql
    region = 'West' AND status != 'Closed'
    ```
  </Tab>
</Tabs>

<Info>
Use **Preview Table Data** to see the table's columns and sample rows before building your filter.
</Info>

A user can belong to multiple groups — their effective access is the **union** of all their groups. To check a group's filters from a member's point of view, use **Test as User** in Kris AI Context Settings.
